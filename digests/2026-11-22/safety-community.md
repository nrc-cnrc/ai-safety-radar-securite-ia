# Community & Tools (2026-11-22)

## Key Discussions

**1. [Evals with error bars: is the new prompt actually better?](https://github.com/anthropics/claude-cookbooks/issues/988)** ([PR](https://github.com/anthropics/claude-cookbooks/pull/989))
Anthropic's cookbook team opened a proposal — quickly followed by an implementation PR — arguing that a single eval score delta after a prompt change is not enough evidence of improvement: an eval is a noisy sample, and teams routinely ship "improvements" that are within the margin of random variation. The recipe adds statistical error bars to prompt-comparison workflows. *Why it matters: as prompt/eval iteration becomes the primary lever for steering model behavior, treating evals with statistical rigor (rather than point estimates) is foundational to trustworthy safety and capability claims.*

**2. [MultiChoiceRegexFilter silently collapses distinct answer choices](https://github.com/EleutherAI/lm-evaluation-harness/issues/4509)** ([fix PR](https://github.com/EleutherAI/lm-evaluation-harness/pull/4522))
A subtle bug in EleutherAI's `lm-evaluation-harness` was discovered where choices that normalize to the same string (e.g., "5" vs "-5", "15" vs "1.5", "Na" vs "NA") get silently mapped to the same letter, with the dictionary keeping only the last one — meaning a correct model response could be scored as wrong (or vice versa) across many benchmarks. *Why it matters: this is one of the most widely used eval harnesses in the field; a silent scoring bug like this can quietly skew published benchmark numbers that inform both capability and safety claims.*

**3. [TransformerLens: BOS-token gradient bug breaks saliency maps for interpretability](https://github.com/TransformerLensOrg/TransformerLens/issues/2045)** ([fix PR](https://github.com/TransformerLensOrg/TransformerLens/pull/2046)) and [GPT-OSS value-bias folding bug](https://github.com/TransformerLensOrg/TransformerLens/pull/2043)
Two correctness bugs were found and fixed in TransformerLens's interpretability tooling: a gradient-based salience helper was silently targeting the BOS token instead of the final token (invalidating any saliency analysis using default settings), and GPT-OSS's attention-sink logits were being mishandled during "compatibility mode," corrupting predictions for that model family. *Why it matters: mechanistic interpretability conclusions are only as reliable as the underlying tooling — silent numerical bugs in widely-used libraries can propagate into published interpretability research.*

**4. [xalgorix security agent's system prompt overstates its own safety guardrails](https://github.com/xalgorix/xalgorix/issues/917)** (related: [#913](https://github.com/xalgorix/xalgorix/issues/913), [#911](https://github.com/xalgorix/xalgorix/issues/911), and [fix release](https://github.com/xalgorix/xalgorix/releases/tag/v4.6.200))
A string of bug reports and fixes in this autonomous pentesting agent show the system prompt telling the model that the runtime "automatically rejects any out-of-scope host" and that all traffic "goes through Caido" — neither of which was actually true in the code. The maintainer patched the prompt to stop making false safety guarantees to the model. *Why it matters: this is a concrete example of the "prompted guardrail vs. enforced guardrail" gap — agents told they're protected by infrastructure that doesn't actually exist are a real-world misalignment/safety risk, especially for an offensive-security tool operating with elevated privileges.*

**5. [SafetyPulse: pre-registered study on refusal-direction drift monitors](https://github.com/PxA-Labs/safetypulse/pull/152)** (Stage 2 results: [#156](https://github.com/PxA-Labs/safetypulse/pull/156), specificity control: [#157](https://github.com/PxA-Labs/safetypulse/pull/157), SafeTune cross-family test: [#151](https://github.com/PxA-Labs/safetypulse/pull/151))
A small but methodologically serious open research project pre-registered and ran hypothesis tests on whether a "refusal-direction drift" signal (CIS) generalizes across models and fine-tuning sources better than weight-norm baselines. Results were mixed: H1/H2 confirmed, H3/H6 refuted (including on 35 SafeTune checkpoints across four model families), with full pre-registration, replication artifacts, and an EMNLP/ACL-format paper. *Why it matters: it's a rare example of community-run, pre-registered falsifiable safety-monitoring research, including honest reporting of negative results — a model for rigor in an area prone to overclaiming.*

## Notable GitHub Releases & Tools

- **[lm-evaluation-harness: Healthcare Escalation Bench, SycoBench-600, reproducible sampling](https://github.com/EleutherAI/lm-evaluation-harness/pull/4648)** — adds a benchmark for escalation behavior in healthcare contexts ([paper](https://arxiv.org/abs/2610.21270)), alongside existing additions like [SycoBench-600](https://github.com/EleutherAI/lm-evaluation-harness/pull/3919) for sycophancy measurement and [reproducible `--sample_seed` limited evaluation](https://github.com/EleutherAI/lm-evaluation-harness/pull/4646) to avoid order-biased partial runs. *Why it matters: expands the standard harness's coverage of safety-relevant failure modes (sycophancy, risky escalation) while improving measurement reliability.*

- **[candle-mi v0.2.3: cross-layer transcoder (CLT) training](https://github.com/mi-for-the-rust-of-us/candle-mi/releases/tag/v0.2.3)** — a Rust mechanistic-interpretability toolkit adds CLT training support and resolves four `zip` security advisories via a dependency bump. *Why it matters: grows the Rust-native tooling ecosystem for scalable interpretability research outside the dominant Python stack.*

- **[boxdawn/guard v0.4.14–v0.4.16: command-safety judging for AI coding agents](https://github.com/boxdawn/guard/releases/tag/v0.4.16)** — a guardrail plugin for Claude Code / Copilot CLI that judges shell commands before execution, with recent fixes for environment-variable spoofing, bash-grammar edge cases, and stdin-piped file reads that could bypass judgment. *Why it matters: directly addresses the practical problem of unsafe command execution by autonomous coding agents, with real adversarial edge-case hardening.*

- **[NVIDIA-NeMo/Guardrails: RAGDefender feature request](https://github.com/NVIDIA-NeMo/Guardrails/issues/2635)** and [0.25 migration/deprecation guide](https://github.com/NVIDIA-NeMo/Guardrails/pull/2595) — a proposed retrieval rail to drop poisoned chunks from knowledge-corruption attacks (PoisonedRAG-style), plus formal deprecation of the legacy `LLMRails`/Colang 1.0 runtime. *Why it matters: signals both forward movement on RAG-specific attack surfaces and the ongoing modernization of a widely-deployed guardrails framework.*
