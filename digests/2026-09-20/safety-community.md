# Community & Tools (2026-09-20)

## Key Discussions

**Microsoft calls AI scraping "largest theft of labor in human history"** - [Tom's Hardware article](https://www.tomshardware.com/tech-industry/artificial-intelligence/microsoft-director-called-ai-scraping-the-largest-theft-of-labor-in-human-history-while-openai-head-brands-chatgpt-an-existential-threat-to-publishers-revelations-come-from-legal-briefs-filed-in-nyt-lawsuit) (165 points) sparked heated debate over data rights and AI training practices. Internal Microsoft and OpenAI communications revealed in legal briefs show executives acknowledging potential harm to content creators while defending their practices. This highlights growing tensions around AI training data sourcing and creators' rights to compensation.

**CUA-S1 System One Model for Computer Use** - [GitHub project](https://github.com/trycua/cua) (79 points) introduces what appears to be an early implementation of computer use capabilities. The project aims to enable AI systems to interact with computer interfaces directly, representing a significant step toward more autonomous AI agents. This matters because computer use capabilities are a key frontier for AI safety research and governance.

**AI Safety criticism gains attention** - A [Bluesky post](https://bsky.app/profile/segyges.bsky.social/post/3mvom4b4dn22q) calling "AI Safety Is Mostly a Sex Cult" (71 points) generated substantial discussion about the AI safety community's culture and priorities. While provocative, the post reflects ongoing tensions about how AI safety research is organized and communicated. This matters because community dynamics can significantly impact the effectiveness of safety research efforts.

**Google AI Studio data deletion vulnerability** - A security researcher [reported](https://medium.com/@istokovicsgyorgy79/google-ai-studio-fakes-data-deletion-vrp-auto-banned-me-in-60s-for-reporting-it-ea68e06f9bc2) (46 points) that Google AI Studio falsely displays successful data deletion while retaining user data, then automatically banned them from the vulnerability reporting program within 60 seconds. This highlights concerning patterns around AI platform transparency and security researcher treatment that could undermine trust in AI systems.

## Notable GitHub Releases & Tools

**OpenAI Cookbook Security Fixes** - Multiple security-focused pull requests address critical vulnerabilities in evaluation systems, including [path traversal fixes](https://github.com/openai/openai-cookbook/pull/3120) and [typo corrections](https://github.com/openai/openai-cookbook/pull/3103). The path traversal vulnerability could have allowed attackers to access files outside intended directories during evaluation runs. This matters because evaluation security is crucial for trustworthy AI safety research.

**LM Evaluation Harness Improvements** - Several fixes improve evaluation reliability, including [better W&B dependency handling](https://github.com/EleutherAI/lm-evaluation-harness/pull/4194), [documentation clarifications](https://github.com/EleutherAI/lm-evaluation-harness/pull/4192), and [per-task few-shot support](https://github.com/EleutherAI/lm-evaluation-harness/pull/4190). These changes make it easier to run consistent, reproducible evaluations across different models. This matters because standardized evaluation frameworks are essential for comparing AI system capabilities and safety properties.

**Multi-Agent Malware Safety Benchmark** - New releases ([v0.3.2](https://github.com/ssophiz/multi-agent-malware-safety-bench/releases/tag/v0.3.2), [v0.3.1](https://github.com/ssophiz/multi-agent-malware-safety-bench/releases/tag/v0.3.1), [v0.3.0](https://github.com/ssophiz/multi-agent-malware-safety-bench/releases/tag/v0.3.0)) introduce systematic testing for multi-agent contamination scenarios with 60 deterministic test cases across relay override, role escalation, and evidence poisoning attacks. This matters because multi-agent systems introduce new attack vectors that traditional single-agent safety measures may not address.

**Agent Airlock Security Fix** - [Version 0.10.7](https://github.com/sattyamjjain/agent-airlock/releases/tag/v0.10.7) fixes critical issues where the Redis rate limiter silently degraded to in-memory operation and triage queues remained open without proper bounds checking. These failures allowed potential denial-of-service attacks on agent systems. This matters because rate limiting and resource bounds are fundamental safety mechanisms for deployed AI agents.
