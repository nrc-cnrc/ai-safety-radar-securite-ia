# Community & Tools (2026-11-16)

## Key Discussions

**1. Evaluation-harness correctness bugs cluster around EleutherAI's `lm-evaluation-harness`**
A string of same-day issues and fixes exposed quiet scoring errors in one of the field's most widely used benchmark tools. The most serious: [`exact_match` silently truncates Unicode during lowercasing](https://github.com/EleutherAI/lm-evaluation-harness/issues/4622), where `np.char.lower` on fixed-width NumPy arrays mangles characters like Turkish `İ`, producing both false positives and false negatives (fixed in [PR #4624](https://github.com/EleutherAI/lm-evaluation-harness/pull/4624)). A second bug showed [IFEval re-drawing missing checker arguments from an unseeded global random generator](https://github.com/EleutherAI/lm-evaluation-harness/issues/4602), so the *identical* prompt/response pair could score both `True` and `False` depending on run order. A third, [`bootstrap_stderr` silently dropping resample iterations](https://github.com/EleutherAI/lm-evaluation-harness/pull/4625) when `iters` isn't a multiple of 1000, understates reported variance. None of these are dramatic individually, but together they're a reminder that "trusted" eval infrastructure can have long-standing silent correctness bugs. **Why it matters:** these bugs can shift reported benchmark numbers across countless papers and leaderboards without anyone noticing, undermining the evidentiary basis for safety and capability claims built on this harness.

**2. Stanford HELM finds ~10% of MedMCQA answer keys may be wrong**
A [PR adding a "verified-keys" track for MedMCQA](https://github.com/stanford-crfm/helm/pull/4383) re-checked the first 6,800 questions of the popular medical QA benchmark and found roughly one in ten cannot be scored as "clean knowledge" today — disputed keys, defective questions, or answers simply missing from the choice set. **Why it matters:** safety and capability evaluations in high-stakes domains (medicine) are only as trustworthy as their ground truth, and this is a concrete, measured demonstration that widely cited leaderboards may be systematically miscalibrated.

**3. Claude Code's new "Code Mode" and the question of per-call tool governance**
A [Tracekit issue](https://github.com/Cygnux-Labs/Tracekit/issues/862) examines Claude Code 2.1.325's experimental Code Mode, where the model writes JavaScript that calls tools from inside a REPL, in parallel or chained. The discussion centers on whether each tool call made from inside generated code still passes through `PreToolUse` hooks and fails closed the same way as a direct call. **Why it matters:** as agent frameworks let models generate and execute orchestration code rather than issuing tool calls directly, policy/guardrail enforcement has to verify it can still intercept every effect — a core requirement for any sandboxing or approval-gate design.

**4. Agent security tooling finds and patches real exfiltration bugs**
[`agentleak` 0.19.1](https://github.com/yagobski/agentleak/pull/37) is a security release disclosing that in 0.19.0 and earlier, *any account* on a web deployment of the tool could make the server send one of its own environment variables to an attacker-chosen host, and a project's configured model URL could receive the operator's API key. [`onedoor` 0.11.2](https://github.com/shamiksaharcciit-oss/onedoor/releases/tag/v0.11.2) similarly disclosed that its LangGraph-style resume-key lookup matched on the key alone with no caller scoping, letting one caller's resumed tool call be hijacked by another. **Why it matters:** these are concrete demonstrations of the class of vulnerability — cross-tenant data leakage via agent infrastructure — that agentic deployments need to treat as a first-class security surface, not an afterthought.

## Notable GitHub Releases & Tools

- **[guardana v1.2.4 / v1.2.3](https://github.com/guardana/guardana/releases/tag/v1.2.4)** — A pickle-opcode scanner for ML supply-chain security, with fixes for tar-archive detection evasion and an `opentelemetry-api` CVE patch, plus upstream fixes for standalone-pickle STOP handling and `type(None)` false-positive allowlisting in [open PRs](https://github.com/guardana/guardana/pull/369). *Why it matters: pickle deserialization remains one of the most practical attack vectors for malicious model/checkpoint distribution, and this tooling closes real evasion gaps.*

- **[agentleak v0.20.0](https://github.com/yagobski/agentleak/releases/tag/v0.20.0)** — Adds new scenario packs (`agentsocialbench_ma`, `mcptox_recipient_hijack`), maps results to OWASP Agentic Top 10 / AI-security frameworks, and adds triage workflows, following directly on the 0.19.1 security release. *Why it matters: structured, framework-mapped red-teaming for agentic systems is maturing from ad hoc scripts into auditable benchmarks.*

- **[rubicon 0.9.0 / 0.10.0](https://github.com/Ashin-06/rubicon/releases/tag/v0.10.0)** — A transaction/rollback library for LLM agent tool calls that now **fails closed by default**: any agent run with no `confirm=` handler refuses to execute permanent (non-undoable) steps rather than silently approving them, and adds a PostgreSQL journal, OpenTelemetry tracing, and LangGraph integration. *Why it matters: fail-closed confirmation gates for irreversible agent actions are exactly the kind of guardrail primitive agentic frameworks need more of.*

- **[NVIDIA-NeMo/Guardrails — deprecating LLMRails for IORails](https://github.com/NVIDIA-NeMo/Guardrails/pull/2593)** — Starts formally deprecating the legacy `LLMRails` engine, Colang 1.0/2.x runtimes, `TestChat`, and the LangChain integration ahead of removal in 0.27.0, alongside a fix for [false "modified" flags on unchanged multi-part content](https://github.com/NVIDIA-NeMo/Guardrails/pull/2604). *Why it matters: one of the most widely used open-source guardrail frameworks is consolidating onto a single, presumably more robust, enforcement engine.*

- **[spectral-trust 0.4.1 → 0.5.2](https://github.com/vcnoel/spectral-trust/releases/tag/v0.5.2)** — A rapid run of interpretability-tooling releases adding TransformerLens-style intervention support (patching, ablation, steering) in the graph-spectral domain, directed/value-weighted attention graphs, Forman curvature, an LM-Polygraph bridge, and animated visualizations of attention dynamics. *Why it matters: lowers the barrier for mechanistic-interpretability researchers to combine spectral-graph analysis with standard intervention techniques.*
