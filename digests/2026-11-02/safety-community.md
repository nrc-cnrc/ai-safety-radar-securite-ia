# Community & Tools (2026-11-02)

## Key Discussions

**1. TransformerLens bug wave exposes subtle interpretability-tooling failures**
A cluster of merged fixes in [TransformerLens](https://github.com/TransformerLensOrg/TransformerLens) this week highlights how fragile mech-interp tooling can be: [`generate(output_logits=True)` was silently returning decoding-constraint scores instead of raw model logits](https://github.com/TransformerLensOrg/TransformerLens/pull/1967) (any no-repeat-ngram/min-length/forced-EOS processing leaked into the logits researchers thought they were analyzing), [`stop_at_layer=n_layers` failed to actually stop](https://github.com/TransformerLensOrg/TransformerLens/pull/1964) (letting `ln_final`/`unembed` run anyway and polluting layer-sweep caches), and [`evals.py` hard-coded `"cuda"`](https://github.com/TransformerLensOrg/TransformerLens/pull/1965), breaking evaluation on non-NVIDIA hardware. None of these would throw an obvious error — they'd just quietly corrupt results. **Why it matters:** interpretability claims are only as trustworthy as the tooling that produces them, and several of these bugs could have silently invalidated published analyses using TransformerLens's generation or evaluation APIs.

**2. Steering-vector research finds models "become" the steered state rather than reporting on it**
[EigenformAI/modulo](https://github.com/EigenformAI/modulo), a tool for letting LLMs introspect and self-steer via activation vectors, shipped a sequence of findings PRs documenting methodological traps in interpretability-via-introspection research: in blinded real-vs-sham sessions, [real steering caused the model to behave as the steered state and essentially stop self-reporting (0.2 reports/session vs 3.2 under sham)](https://github.com/EigenformAI/modulo/pull/15), while sham sessions produced confident, detailed (but confabulated) narration that steering had worked. A separate fix found that [models were anchoring on the exact example call given in the system prompt](https://github.com/EigenformAI/modulo/pull/17) rather than choosing autonomously — undermining claims that "models like to turn up sycophancy." **Why it matters:** this is a concrete, reproducible demonstration of how self-report-based interpretability experiments can manufacture false signals from prompt artifacts and confabulation, a caution relevant to the broader "model introspection" research agenda.

**3. A wave of eval-correctness bugs across major benchmark harnesses**
Independently, three widely-used eval frameworks surfaced scoring bugs this week: [EleutherAI's lm-evaluation-harness had multiple IFEval checkers matching substrings instead of whole words/structure](https://github.com/EleutherAI/lm-evaluation-harness/issues/4506) (counting "cat" inside "category"), plus a [MultiChoiceRegexFilter collision bug](https://github.com/EleutherAI/lm-evaluation-harness/issues/4509) silently merging distinct answer choices; [Stanford HELM's BBQ bias metric scaled the ambiguous-bias score by overall accuracy instead of ambiguous-only accuracy](https://github.com/stanford-crfm/helm/pull/4373), understating bias scores whenever disambiguated questions were easy; and [OpenJudge's JSON grader let Python's bool/int equivalence silently match `true` against `1`](https://github.com/agentscope-ai/OpenJudge/pull/205), plus [an order-dependent matching bug in unordered JSON comparison](https://github.com/agentscope-ai/OpenJudge/pull/207). **Why it matters:** these are the measurement infrastructure underlying safety and capability benchmarking — quiet scoring bugs can make models look safer, more biased, or more/less capable than they are, with downstream effects on leaderboards and governance decisions.

**4. Agent sandbox-escape and guardrail hardening accelerates**
[sattyamjjain/agent-airlock](https://github.com/sattyamjjain/agent-airlock) shipped defenses against [CVE-2026-120338](https://github.com/sattyamjjain/agent-airlock/pull/447), a Pyodide-on-Deno sandbox-escape class where caller-supplied Python in a code-execution tool could reach the host filesystem/network, plus a [default deny-list for paths agents use to persist or hijack IDE behavior](https://github.com/sattyamjjain/agent-airlock/pull/442). In parallel, [batrapulkit/squidbrake](https://github.com/batrapulkit/squidbrake) (an MCP approval-gateway) expanded rule packs for [Kubernetes](https://github.com/batrapulkit/squidbrake/pull/158) and [Jira/Confluence](https://github.com/batrapulkit/squidbrake/pull/157), and added [Telegram-based human-approval notifications](https://github.com/batrapulkit/squidbrake/pull/159). **Why it matters:** as agentic coding/ops tools proliferate, the "human-in-the-loop + sandboxed execution" layer is becoming a de facto safety boundary, and these fixes show real exploitability (not just theoretical risk) in that layer.

## Notable GitHub Releases & Tools

**[agent-airlock v0.10.29–v0.10.31](https://github.com/sattyamjjain/agent-airlock/releases/tag/v0.10.31)** — Three rapid security releases closing a code-sandbox host-bridge vulnerability (CVE-2026-120338 class), adding default-deny persistence paths, and fixing three externally-reported advisories (path containment, endpoint-policy bypass). *Why it matters:* shows an actively maintained, security-first guardrail layer for agent tool use responding to real-world exploit classes within days.

**[squidbrake v0.14.15–v0.14.17](https://github.com/batrapulkit/squidbrake/releases/tag/v0.14.17)** — Adds Telegram approval notifications with one-tap approve/reject, fixes anonymous usage telemetry for Docker/background gateway installs, and speeds up usage-count syncing from hours to minutes. *Why it matters:* an open-source "circuit breaker" for MCP agent tool calls is maturing its human-approval UX, lowering friction for teams to adopt human oversight on autonomous agents.

**[undercurrent v0.2.0](https://github.com/wrynx/undercurrent/releases/tag/v0.2.0)** — Adds an experimental vLLM adapter with graph-mode `residual_stream` capture that preserves CUDA graphs and `torch.compile`, letting interpretability researchers extract activations from production-speed inference rather than only research-mode HF models. *Why it matters:* closes the gap between interpretability tooling (usually slow, eager-mode) and how models are actually served, enabling interpretability work at realistic inference scale.

**[NVIDIA-NeMo/Guardrails PR #2510](https://github.com/NVIDIA-NeMo/Guardrails/pull/2510)** — Adds configurable "decision model" input/output rails, letting applications point at a custom moderation endpoint to block messages before they reach or leave the main model.
