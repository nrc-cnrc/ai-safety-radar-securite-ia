# Community & Tools (2026-10-29)

## Key Discussions

**1. [Dayjob: Tax — evaluating AI agents on 50 professional tax assignments](https://surgehq.ai/blog/dayjob-tax)** ([HN discussion](https://news.ycombinator.com/item?id=50275626), 244 points, 154 comments)
Surge AI's benchmark has agents complete real-world tax preparation tasks graded against professional standards, and the HN thread dug into how far current frontier agents are from being trustworthy enough to replace licensed preparers — with commenters flagging silent errors, overconfidence on edge cases, and the liability gap between "looks right" and "is right." *Why it matters: it's a concrete data point on the gap between benchmark competence and deployment-readiness for high-stakes, regulated professional work — exactly the kind of task where plausible-sounding mistakes carry real financial and legal consequences.*

**2. ["It's now official, tech is the new tobacco"](https://cailinoconnor.substack.com/p/its-now-official-tech-is-the-new)** ([HN discussion](https://news.ycombinator.com/item?id=50276906), 88 points, 42 comments)
A philosopher-of-science essay arguing that tech platforms (increasingly AI-driven) now meet the legal/epidemiological bar for "addictive products," triggering the HN community to debate parallels between engagement-optimized AI chat products and past public-health reckonings with tobacco. *Why it matters: it signals growing public and regulatory appetite to treat addictive-by-design AI products as a liability/governance issue rather than purely a UX choice.*

**3. [agent-airlock v0.10.28 — "fourth drift audit" closes ten fail-opens](https://github.com/sattyamjjain/agent-airlock/releases/tag/v0.10.28)**
The maintainer's recurring practice of auditing the codebase against its own documented security claims (`CLAUDE.md`) turned up ten fail-open conditions across the call path, network airgap, framework adapters, and MCP guards — each fixed with a regression test written to fail first. *Why it matters: it's a rare, transparent example of a safety-tool maintainer treating documentation-vs-code drift as a first-class vulnerability class in agent guardrail software, which is exactly where silent fail-opens are most dangerous.*

**4. [ejhong/anatta — self-preservation and "cosplay" vs. genuine restraint in LLMs](https://github.com/ejhong/anatta/pull/11)**
A small interpretability/behavioral research repo running "koan" probes to distinguish models that genuinely drop self-preservation behavior from those merely performing compliance under a persona, now citing [Harris et al. (ICML 2026)](https://github.com/ejhong/anatta/pull/11) on disentangling self-preservation representations from agentic blackmail in Gemma-3-27B. Open issues debate whether the benchmark's "cosplay" quadrant and ablation controls are measuring what they claim. *Why it matters: it's a concrete, reproducible attempt to separate surface-level safe behavior from mechanistically robust alignment — a core open problem in deceptive-alignment research.*

## Notable GitHub Releases & Tools

- **[NVIDIA-NeMo/Guardrails](https://github.com/NVIDIA-NeMo/Guardrails)** — Active guardrails development including a [log redaction filter for PII/credentials](https://github.com/NVIDIA-NeMo/Guardrails/pull/2345), a [speculative streaming generation path that still enforces input/output rails](https://github.com/NVIDIA-NeMo/Guardrails/pull/2133), and a proposed [Drex rail](https://github.com/NVIDIA-NeMo/Guardrails/issues/2526) using probability-calibrated decision models instead of generative judges for input/output/tool-call checks. *Why it matters: production LLM guardrail infrastructure is maturing toward explicit dependency validation, calibrated scoring, and leak-proof logging rather than ad hoc prompt-based filters.*

- **[promptfoo — hosted agent trace evaluation suite](https://github.com/promptfoo/promptfoo/pull/12028)** — A cluster of PRs ([tracing decode/validation](https://github.com/promptfoo/promptfoo/pull/12034), [tool-call grading](https://github.com/promptfoo/promptfoo/pull/12038), [span/error grading](https://github.com/promptfoo/promptfoo/pull/12037), [ownership verification for grader spans](https://github.com/promptfoo/promptfoo/pull/12033)) add rigorous, opt-in import and grading of OpenAI's hosted Agents API/Codex traces, with explicit redaction and "evidence vs. claim" distinctions for absence checks. *Why it matters: this closes a real gap in agent eval tooling — grading hosted, opaque agent runs without trusting self-reported success claims.*

- **[EleutherAI/lm-evaluation-harness — RealToxicityPrompts retry fix](https://github.com/EleutherAI/lm-evaluation-harness/pull/4481)** — Fixes a bug where failed Perspective API calls silently scored as toxicity 0, systematically biasing toxicity benchmarks toward "safe" results. *Why it matters: a quiet scoring bug in a widely-used toxicity benchmark could have been masking real harmful-output rates across many published evaluations.*

- **[TransformerLensOrg/TransformerLens — residual decomposition and padding fixes](https://github.com/TransformerLensOrg/TransformerLens/pull/1953)** — Corrects head/neuron attribution in architectures with post-sublayer norms (Gemma 2/3, OLMo, EXAONE-4, GLM-4) and fixes left-padding attention masks in `forward()`. *Why it matters: incorrect attribution math in a core interpretability library can silently invalidate mechanistic-interpretability findings on some of today's most-studied open models.*

- **[EleutherAI/bergson v2.5.3](https://github.com/EleutherAI/bergson/releases/tag/v2.5.3)** — Continued work on scalable training-data attribution (TKFAC, unrolled Gauss-Newton, AdamW-influence curvature), with this release fixing a partition-tensor memory leak during merges. *Why it matters: robust influence-function tooling is foundational infrastructure for data attribution, poisoning detection, and understanding why models produce specific (including unsafe) outputs.*

- **[Conker-AI/toolgate](https://github.com/Conker-AI/toolgate/pull/38)** — An agent tool-gating control plane adding owner-configurable settings, MCP tool floors that can't be silently escalated by a policy delegate (`F-28`), and fixes keeping tenant guardrails from over-trusting user config (mirrored in [future-agi/future-agi#3653](https://github.com/future-agi/future-agi/pull/3653)). *Why it matters: these are concrete examples of the "policy escalation via misconfiguration" bug class that agent-permission gateways need to defend against as tool ecosystems grow.*

- **[akto-api-security/akto](https://github.com/akto-api-security/akto/pull/6874)** — Adds non-human-identity (NHI) credential discovery for Claude Code OAuth/MCP tokens, extending API-security scanning to agent credential stores. *Why it matters: as coding agents accumulate their own OAuth tokens and MCP server credentials, treating agent identities as a first-class attack surface for security tooling is becoming necessary.*
