# Community & Tools (2026-11-26)

## Key Discussions

**1. OpenAI's automated "distillation" bans draw scrutiny with no human appeal path**
A [GitHub issue on openai-cookbook](https://github.com/openai/openai-cookbook/issues/3062) describes a ChatGPT Pro account permanently deactivated for suspected "distillation" with an automated appeal instantly rejected by a bot and no human review available. While filed against the cookbook repo (likely for lack of a better venue), it surfaces a recurring governance problem: enforcement actions against suspected misuse of frontier models increasingly rely on opaque automated systems with no accountable escalation path. **Why it matters:** as labs tighten anti-distillation enforcement to protect model IP, the lack of due process in automated trust & safety decisions is becoming a live AI governance concern, not just a UX complaint.

**2. Path traversal in OpenAI's own realtime eval harnesses**
A [security audit finding (BUG-001)](https://github.com/openai/openai-cookbook/issues/3132) shows that realtime eval harnesses build filesystem paths directly from unvalidated `example_id`/`simulation_path`/`audio_path` fields in dataset CSVs and simulation JSONs, so a hostile data file can read/write outside the eval sandbox. **Why it matters:** eval harnesses are exactly the kind of "trusted" tooling that gets pointed at untrusted or adversarially-sourced data (red-team corpora, community benchmarks), so path-traversal bugs here are a reminder that safety tooling itself needs its own threat model.

**3. CVE triage and fail-open fixes in agent-airlock's MCP/network guardrails**
[sattyamjjain/agent-airlock](https://github.com/sattyamjjain/agent-airlock) ran a dense week of security hardening: a [metadata-endpoint SSRF gap](https://github.com/sattyamjjain/agent-airlock/pull/540) (GCP's short `metadata` host and Alibaba's `metadata.aliyuncs.com` weren't blocked), a [deadlock in the network airgap](https://github.com/sattyamjjain/agent-airlock/pull/536) that could hang a guarded call forever, and a [batch of fail-opens](https://github.com/sattyamjjain/agent-airlock/pull/537) found by auditing the project's own CLAUDE.md claims against the code (e.g. a `ReadOnlySQLGuard` that stopped reading nested SQL after a related fix). CVE issues like [CVE-2026-67543](https://github.com/sattyamjjain/agent-airlock/issues/503) and [CVE-2026-130008](https://github.com/sattyamjjain/agent-airlock/issues/532) are tracked and triaged against the guard suite. **Why it matters:** this is a textbook case of "guardrails need guardrails" — tools meant to sandbox agentic systems are themselves accumulating CVEs and fail-open bugs, and the public, continuously re-run benchmark discipline (prompt-injection matrices, OWASP matrices) is a good model for how such tools should be validated.

**4. Credential-exfiltration coverage gaps in coding-agent policy engines**
[Cygnux-Labs/Tracekit](https://github.com/Cygnux-Labs/Tracekit) is actively closing gaps where credential-reading CLI commands (`gh auth token`, `pass`, `security find-*-password`, `ssh-add -L`, etc.) have policy coverage for direct shell execution but not when routed through an MCP command-runner tool — see [the issue](https://github.com/Cygnux-Labs/Tracekit/issues/1083) and its [fix](https://github.com/Cygnux-Labs/Tracekit/pull/1160). A related thread covers deciding artifact-create/update risk tiers by inspecting what OpenCode/Kilo Code providers actually send ([#988](https://github.com/Cygnux-Labs/Tracekit/issues/988)). **Why it matters:** as more coding agents route tool calls through MCP wrappers, policy engines built for direct CLI invocation need systematic re-auditing for "same action, different transport" bypasses — a pattern likely to recur across the whole agent-security tooling ecosystem.

**5. A governance proposal for agent "denial fatigue" in Prismor**
A [proposal in PrismorSec/prismor](https://github.com/PrismorSec/prismor/issues/1021) asks for a mechanism to hand a session to a human after repeated policy denials, rather than letting the agent keep retrying blocked actions indefinitely. **Why it matters:** this is a small but telling design question for human-in-the-loop safety systems — overly strict allow/deny gating without an escalation path can push agents (or their operators) toward workarounds, so "denial breaker" UX is a meaningful part of making policy enforcement actually durable in practice.

## Notable GitHub Releases & Tools

- **[agent-airlock v0.10.36](https://github.com/sattyamjjain/agent-airlock/releases/tag/v0.10.36)** — Fixes a network-airgap deadlock, adds a minimum release-age gate for npm/PyPI packages ([GHSA-h82f-cjm4-g22r](https://github.com/sattyamjjain/agent-airlock/pull/519)), an option-injection check for tool arguments (CVE-2026-114496), and widens the read-only SQL guard. *Why it matters:* a concrete, actively-maintained reference implementation for sandboxing MCP/agent tool calls against real disclosed CVEs.

- **[Guardana v1.4.2](https://github.com/guardana/guardana/pull/408)** (and [v1.4.1](https://github.com/guardana/guardana/releases/tag/v1.4.1)) — Model-supply-chain scanner fixes: handles zip members that decode past their declared size, catches files excluded by `.guardanaignore` patterns that loaders still open by content-sniffed bytes, and closes gaps in pickle-opcode and streamed-tar scanning. *Why it matters:* pickle/weights-file scanning is a core defense against malicious model artifacts, and these are exactly the edge cases (compression tricks, ignore-pattern bypasses) real attackers would exploit.

- **[Prismor v1.80.6](https://github.com/PrismorSec/prismor/releases/tag/v1.80.6)** — Adds post-tool-use output capture for Crush, OpenHands and all Grok tools (previously unmonitored), a dashboard for reviewing agents' "Always Allow" rules across Claude Code/Codex/Cursor/Antigravity, and keeps the LLM policy judge inside its hook deadline so a slow verdict can't block all subsequent tool calls. *Why it matters:* closing hook-coverage gaps across different agent harnesses is essential for any runtime policy layer to provide consistent protection.

- **[hackfloor v0.2.1](https://github.com/ranjeetds/hackfloor/releases/tag/v0.2.1)** — A reward-hacking detection tool; adds `HF-WRONG` (a 15th built-in reward-hacking probe), switches bounded-partial-credit findings to informational-only, and tightens statistical significance criteria (one-sided sign test) for flagging reproducible "hack-passes." *Why it matters:* as RL/RLHF pipelines proliferate, having a dedicated, statistically-principled probe suite for reward hacking is a useful complement to interpretability and red-teaming tools.

- **[PyRIT PR #4667](https://github.com/microsoft/PyRIT/pull/4667)** — Adds native PDF/file input support (`binary_path`) to `OpenAIChatTarget`/`OpenAIResponseTarget`, enabling document-based red-team testing that wasn't previously possible. Also new this cycle: a [MultiJail dataset loader](https://github.com/microsoft/PyRIT/pull/4510) (315 unsafe prompts across 10 languages) and a new [Learn AI Red Teaming guide + FAQ](https://github.com/microsoft/PyRIT/pull/4665). *Why it matters:* expands Microsoft's red-teaming framework's attack surface coverage (multimodal, multilingual) and onboarding for a widely-used safety tool.
