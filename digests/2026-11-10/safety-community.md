# Community & Tools (2026-11-10)

## Key Discussions

**1. TransformerLens interpretability bridge is quietly accumulating architecture-coverage bugs** — A cluster of [PRs](https://github.com/TransformerLensOrg/TransformerLens/pull/2007) this week fixed residual-decomposition and per-head attribution failures across [Falcon-H1](https://github.com/TransformerLensOrg/TransformerLens/pull/2002) (parallel Mamba+attention), [Zamba2/RecurrentGemma](https://github.com/TransformerLensOrg/TransformerLens/pull/2003), [LFM2](https://github.com/TransformerLensOrg/TransformerLens/pull/2001), [XGLM](https://github.com/TransformerLensOrg/TransformerLens/pull/2008) and [JetMoE](https://github.com/TransformerLensOrg/TransformerLens/pull/2007). In parallel, [JacobianLens gained provenance import support](https://github.com/TransformerLensOrg/TransformerLens/pull/2010) for the published "J++" lens format from `safety-research/jpp_lens`, and a [proposal](https://github.com/TransformerLensOrg/TransformerLens/issues/1991) seeks to extend it with filtered readouts. A flaky [faithfulness test](https://github.com/TransformerLensOrg/TransformerLens/issues/1993) was also found to pass/fail nondeterministically on float32 rounding, masking whether circuit-recovery metrics are even graded correctly. **Why it matters:** mechanistic interpretability results are only as trustworthy as the library computing them — silent architecture-specific bugs in hybrid/SSM models could be quietly corrupting published circuit analyses on newer model families.

**2. A steady drumbeat of MCP server command-injection CVEs is exposing the agent tool-calling attack surface** — [sattyamjjain/agent-airlock](https://github.com/sattyamjjain/agent-airlock) is tracking a wave of HIGH-severity CVEs (CVSS 7.5–7.8) across MCP integrations: [Kali-GPT](https://github.com/sattyamjjain/agent-airlock/issues/390), [esp-mcp](https://github.com/sattyamjjain/agent-airlock/issues/388), [sf-mcp](https://github.com/sattyamjjain/agent-airlock/issues/387), [DroidMind](https://github.com/sattyamjjain/agent-airlock/issues/385), and a [SQL injection in Tabularis](https://github.com/sattyamjjain/agent-airlock/issues/393) — nearly all CWE-78 OS command injection via unsanitized tool arguments. The project's own [v0.10.32/0.10.33 releases](https://github.com/sattyamjjain/agent-airlock/releases/tag/v0.10.33) close "fail-open" gaps where a granted DANGEROUS-capability tool was never actually checked for sandbox enforcement at call time. **Why it matters:** as MCP becomes the de facto tool-calling standard, the ecosystem is discovering — one CVE at a time — that many server implementations have no meaningful input sanitization, making prompt-injection-to-RCE a realistic chain.

**3. Guardrail systems are English-centric, leaving non-English jailbreaks undetected** — An [issue on NVIDIA-NeMo/Guardrails](https://github.com/NVIDIA-NeMo/Guardrails/issues/2570) reports that the non-LLM jailbreak detector (perplexity heuristics + embedding classifier) misses Polish-language jailbreaks equivalent to English ones it catches. **Why it matters:** this is a concrete, reproducible example of a known but under-addressed safety gap — deployed guardrails trained/tuned primarily on English corpora may offer far weaker protection for non-English users, a multilingual safety blind spot with real-world deployment implications.

**4. Aider ships a real path-traversal fix after a user-reported escape vector** — A [security issue](https://github.com/Aider-AI/aider/issues/5972) found that `--yes-always` bypasses path confirmation, letting a model-suggested `../../.bashrc`-style path write outside the repo. The fix, [PR #5974](https://github.com/Aider-AI/aider/pull/5974), canonicalizes paths with `Path.resolve()` and refuses writes outside the repo tree. **Why it matters:** this is a textbook example of the agentic-coding threat model — an LLM's own output (not an external attacker) can trigger unintended filesystem access once a human removes the confirmation gate, and most coding agents still don't guard against this by default.

**5. Evaluation-harness correctness bugs are quietly skewing benchmark comparisons** — [EleutherAI/lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness) has several open issues affecting benchmark trustworthiness: [`model_comparator.py` uses an unpaired z-test on paired data](https://github.com/EleutherAI/lm-evaluation-harness/issues/3831) (likely overstating significance), [`bootstrap_stderr` silently drops resamples](https://github.com/EleutherAI/lm-evaluation-harness/issues/4288) when `bootstrap_iters` isn't a multiple of 1000, and a [fixed PR](https://github.com/EleutherAI/lm-evaluation-harness/pull/4577) found that a valid BOS token ID of `0` was being silently discarded in favor of EOS, changing loglikelihood conditioning. **Why it matters:** these are the kinds of silent statistical and tokenization bugs that can make model-vs-model comparisons in papers and leaderboards subtly wrong without anyone noticing.

## Notable GitHub Releases & Tools

- **[pytest-wardenbot v0.6.0](https://github.com/wardenbot-ai/pytest-wardenbot/releases/tag/v0.6.0)** — An agent red-teaming pytest plugin now runs fully local-first (Ollama/vLLM/llama.cpp, no API key, with a test proving no network egress) and adds first-class [LangGraph](https://github.com/wardenbot-ai/pytest-wardenbot/pull/47) and [Claude Agent SDK](https://github.com/wardenbot-ai/pytest-wardenbot/pull/48) targets. *Why it matters: lowers the barrier to CI-integrated adversarial testing of agent frameworks without sending traffic to cloud providers.*

- **[safetypulse v0.1.1](https://github.com/PxA-Labs/safetypulse/releases/tag/v0.1.1)** — First PyPI release of a circuit-interpretability-based safety scoring tool (`cis_circ` metric), shipped with Trusted Publishing (OIDC, no stored tokens) and a [fix](https://github.com/PxA-Labs/safetypulse/pull/121) that rejects empty audit splits and unvalidated reference values that previously could silently produce a passing report on bad input. *Why it matters: closing silent-pass failure modes is exactly the kind of rigor safety-evaluation tooling needs before adoption.*

- **[argus-probe v1.8.1](https://github.com/gy15901580825/Argus/releases/tag/v1.8.1)** — Patches 13 CVEs pulled in transitively via `filelock` and adds five new system-prompt/secret-extraction chat probes, plus browser-agent probes that now [require execution evidence](https://github.com/gy15901580825/Argus/pull/216) for OS-command findings rather than flagging on download alone. *Why it matters: a red-teaming tool for browser/agentic targets getting more precise about what counts as a real exploit (vs. a benign download) reduces false-positive noise in agent security testing.*

- **[DiagSafe](https://github.com/Tencent-Hunyuan/DiagSafe/pull/3)** (Tencent Hunyuan) — New ability to [judge the chain-of-thought](https://github.com/Tencent-Hunyuan/DiagSafe/pull/3) of reasoning models, not just their final answer, via configurable `answer_key` modes. *Why it matters: safety evaluation has mostly judged final outputs; scoring the hidden reasoning trace itself is increasingly necessary as "harmless answer, harmful reasoning" becomes a known failure mode.*
