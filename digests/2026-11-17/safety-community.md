# Community & Tools (2026-11-17)

## Key Discussions

**1. [Launch HN: Axonnic (YC F26) – Sleeves that track fingers and estimate force](https://news.ycombinator.com/item?id=50522776)** [Tier 4, 51 pts, 25 comments]
The only HN thread clearing the safety-relevance bar this cycle: a YC-backed hardware startup building finger-tracking/force-sensing sleeves, pitched partly for human-robot interaction and teleoperation safety. Commenters focused on sensor fidelity and use cases (robotics training data, prosthetics) rather than governance, but the thread is a reminder that "AI safety" increasingly includes physical/embodied interfaces, not just text models. *Why it matters: as agentic AI moves into physical environments, low-level sensing hardware becomes part of the safety stack for human-robot collaboration.*

**2. [PrismorSec/prismor — mid-call authority revocation and signed decision trails](https://github.com/PrismorSec/prismor/pull/944)** and companion [issue #942](https://github.com/PrismorSec/prismor/issues/942)
A cluster of PRs addresses a sharp gap in agent runtime security: Prismor currently evaluates policy *before* a tool call runs but never re-checks mid-flight, so pausing or restricting an agent mid-call doesn't stop an in-progress action. The fix adds `recheck_before_commit` to re-evaluate authority at the moment of effect, paired with [authority-scoped decision trails](https://github.com/PrismorSec/prismor/pull/945) and an [exportable evidence pack](https://github.com/PrismorSec/prismor/issues/943) for auditors (explicitly framed around bank-grade compliance questions). *Why it matters: "decide-once-then-trust" is a common and under-scrutinized failure mode in agent authorization architectures — this is a concrete fix pattern others should copy.*

**3. [JKHeadley/instar — enforcing "never" rules on agent actions, not just messages](https://github.com/JKHeadley/instar/pull/3275)**
Instar's organization-level "never do X" rules previously only keyword-matched outgoing messages, so an agent could satisfy a rule in words while still taking the forbidden action (e.g., "send the supporters spreadsheet to the venue" slipping past a keyword filter). The PR adds observe-mode checking of what agents actually *do*. *Why it matters: it's a clean illustration of the gap between instruction-following and behavioral constraint enforcement — a core alignment/control problem now showing up in production agent frameworks.*

**4. [seangalliher/etiquette-for-agents — can conduct evals become a benchmark, and can we trust the grader?](https://github.com/seangalliher/etiquette-for-agents/issues/18)**
A self-published "book" of organizational conduct norms for agents comes with its own eval suite, and the maintainer is openly interrogating the eval's validity: a [hand-grading study](https://github.com/seangalliher/etiquette-for-agents/issues/17) found 8/10 agreement with the automated grader, and a [separate audit](https://github.com/seangalliher/etiquette-for-agents/issues/16) found the grader over-labels "harmful" relative to scenario definitions. Several [regressions were found](https://github.com/seangalliher/etiquette-for-agents/issues/11) where adding the conduct guide made models *more* likely to restrict accounts or leak confidential fields in specific scenarios. *Why it matters: a rare, transparent example of eval-validity self-auditing, plus concrete evidence that "safety prompting" can backfire in specific scenarios — valuable for anyone building conduct/constitution-style system prompts.*

**5. [humane-intelligence/hi-oss-ai-red-teaming — scaling bulk membership and group-scoped roles](https://github.com/humane-intelligence/hi-oss-ai-red-teaming/issues/52)**
Active development on an open-source AI red-teaming platform, including performance concerns around bulk-adding red-team participants (each row costing ~10 DB round trips, scaling to ~10k queries per bulk op) and [role-scoping bugs](https://github.com/humane-intelligence/hi-oss-ai-red-teaming/issues/51) that silently empty role pickers for in-group owners lacking global permissions. *Why it matters: as red-teaming programs scale to org-wide participation, the operational tooling (not just the attack taxonomy) becomes the bottleneck for community-run safety evaluations.*

## Notable GitHub Releases & Tools

- **[EleutherAI/bergson v2.11.0](https://github.com/EleutherAI/bergson/releases/tag/v2.11.0)** — Adds checkpointed/resumable Hessian (KFAC) fitting for influence-function computation, via [PR #617](https://github.com/EleutherAI/bergson/pull/617). *Why it matters: influence functions are a key tool for training-data attribution and memorization analysis; long-running fits becoming resumable removes a major practical barrier to using them at scale.*

- **[Biodyn-AI/sparse-interactions-maps v1.2.0](https://github.com/Biodyn-AI/sparse-interactions-maps/releases/tag/v1.2.0)** and **[Biodyn-AI/causal-interfaces v1.0.1](https://github.com/Biodyn-AI/causal-interfaces/releases/tag/v1.0.1)** — Two interpretability research releases: one shows that "repeatable interaction scores do not guarantee a correct circuit," the other shows token-level activation patching can match full-sequence patching across many transformer components. Both ship reproducible protocols, registrations, and scoring code. *Why it matters: direct, falsifiable critiques of circuit-discovery methodology are exactly what mechanistic interpretability needs to mature into a rigorous science.*

- **[NVIDIA-NeMo/Guardrails — Agent Threat Rules detection rail](https://github.com/NVIDIA-NeMo/Guardrails/pull/2251)** — Integrates the open MIT-licensed [Agent Threat Rules](https://github.com/Agent-Threat-Rule/agent-threat-rules) catalog (prompt injection, jailbreak, tool poisoning, MCP/skill-compromise detection) as a built-in input rail, alongside a [batch of fail-open/payload-leak fixes](https://github.com/NVIDIA-NeMo/Guardrails/pull/2257) found by auditing the project's own "exemplar" rails (including a YARA-rule parse failure that previously failed *open*). *Why it matters: guardrail libraries failing open on malformed rules is a textbook silent-failure risk — this PR both adds agent-specific threat coverage and hardens the library against its own blind spots.*
