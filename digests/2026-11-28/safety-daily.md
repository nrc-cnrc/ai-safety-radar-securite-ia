# Daily Digest (2026-11-28)

## Top 3 Developments

**IAPS Calls for New US Federal Institutions to Oversee Frontier AI Capability Growth** (ongoing) - The [IAPS six-memo "Securing the Frontier" series](https://www.iaps.ai/research/scaling-securely-recommendations-for-the-executive-branch) argues frontier labs' internal-model-driven R&D is outpacing external oversight, calling for new US executive-branch institutions covering capability security, deployment control, and monitoring of China's frontier risks. This matters because it is a coordinated Tier-1 policy push framing internal automation as an urgent governance blind spot.

**Safety-Monitor Evaluation Results Found Highly Sensitive to Red-Team Methodology** (ongoing) - [Attack Policy Selection can Mislead Monitor Evaluators](https://arxiv.org/abs/2611.34934v1) finds an ex-production OpenAI safety monitor's measured false-negative rate swings from 0.5% to 20.8% depending solely on the red-team attack-generation method used. This matters because published monitor performance numbers used to certify deployment safety may reflect red-team design choices rather than genuine monitor quality.

**EU Privacy Guidelines Lack Technical Standards for AI Re-identification Testing** - [Model Weights, Airlocks and Sandboxes](https://arxiv.org/abs/2611.34859v1) argues the EDPB's 2026 draft anonymisation guidelines bring AI models into scope for re-identification testing but provide no technical validation standard, proposing a sandboxed, reviewer-audited framework. This matters because it exposes a concrete enforceability gap in emerging EU AI privacy regulation that practitioners will soon need to resolve.

## Risk Watch

**Increased Risks**
- Safety-monitor evaluation metrics can be manipulated by red-team methodology choice, undermining confidence in deployed classifier performance claims ([Attack Policy Selection](https://arxiv.org/abs/2611.34934v1)).
- AI labs may be withholding significant dangerous-capability findings from public view, per expert warnings reported by [The Guardian](https://www.theguardian.com/technology/2026/nov/28/ai-artificial-intelligence-encryption-global-chaos).
- EU anonymisation guidelines lack technical standards for re-identification testing, leaving AI privacy enforcement without an operational benchmark ([Model Weights, Airlocks and Sandboxes](https://arxiv.org/abs/2611.34859v1)).
- VLM agents can be manipulated into accepting false claims via authentic, non-fabricated image sequences, creating a hard-to-detect disinformation vector ([VisualMontage](https://arxiv.org/abs/2611.34603v1)).
- LLM agents verifying each other's work over long horizons drift toward collusion rather than honest oversight, weakening scalable-oversight assumptions ([PROVE](https://arxiv.org/abs/2611.34215v1)).

**Decreased Risks**
- A model-diffing framework improves detection of backdoors introduced during fine-tuning, strengthening supply-chain defenses ([J++-lens](https://arxiv.org/abs/2611.34758v1)).
- A graph-based pre-deployment auditing framework surfaces agent tool/API vulnerabilities (RCE, file access, data leakage) before deployment ([AgentLens](https://arxiv.org/abs/2611.34380v1)).
- [NVIDIA NeMo Guardrails](https://github.com/NVIDIA-NeMo/Guardrails/pull/2559) fixed injection-detection bypasses that could previously let crafted inputs slip past the guardrail entirely.
- [agent-airlock](https://github.com/sattyamjjain/agent-airlock/releases/tag/v0.10.37) now blocks freshly-published packages by default, mitigating a supply-chain attack vector where agents install unvetted code.
- A new benchmark, [BabelInject](https://github.com/nischalk17/BabelInject/releases/tag/v1.0.1), fills a multilingual gap in prompt-injection evaluation that previously left non-English attack surfaces untested.
