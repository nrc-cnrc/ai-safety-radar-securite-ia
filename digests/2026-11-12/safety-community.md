# Community & Tools (2026-11-12)

## Key Discussions

**1. HumanEval/MBPP scoring can be gamed with a rigged `__eq__`** — [EleutherAI/lm-evaluation-harness#4585](https://github.com/EleutherAI/lm-evaluation-harness/issues/4585) and the fix in [PR #4587](https://github.com/EleutherAI/lm-evaluation-harness/pull/4587)
A reported bug shows that a completion returning an object whose `__eq__` always returns `True` gets a perfect `pass@1 = 1.0` on HumanEval and MBPP, since both rely on `assert candidate(...) == expected`. The fix rejects such "always-equal" objects as scoring shortcuts. **Why it matters:** this is exactly the kind of reward-hacking/benchmark-gaming vulnerability that agentic or RL-trained coding models could exploit (deliberately or by selection pressure), silently inflating capability claims built on these widely-used benchmarks.

**2. HELM's `quasi_exact_match` strips operators, miscrediting 43% of synthetic-reasoning scores** — [stanford-crfm/helm#4381](https://github.com/stanford-crfm/helm/issues/4381)
`normalize_text` removes all punctuation before comparison, but in the `synthetic_reasoning` scenario the operators (`+ - * =`) *are* the content being tested — so `X = Y + Y` and `X + Y = Y` are scored as equivalent. **Why it matters:** a widely cited eval harness has been silently misgrading reasoning tasks, a reminder that "trusted" leaderboard numbers need periodic adversarial audits.

**3. Measured prompt-injection gaps in agent tool-calling, with concrete attack-stop rates** — [xMannixx/Agent-Security-Guard issues #39–42](https://github.com/xMannixx/Agent-Security-Guard/issues/39)
A series of issues quantify where prompt-injection defenses fail: MCP tool results and shell/curl output weren't treated as "outside content" (only 96/480 attacks stopped), write-capable MCP tools ran unchecked after web content (53% stop rate), and `browser_exec` let injected pages fill bank forms with 0/96 stopped. **Why it matters:** this is rare, benchmark-backed transparency about where today's agent guardrails actually break, rather than marketing claims — directly useful for anyone deploying tool-using agents.

**4. MCP's 2026-07-28 lifecycle spec makes tool-definition swapping and rug-pulls "routine"** — [wardenbot-ai/pytest-wardenbot#61](https://github.com/wardenbot-ai/pytest-wardenbot/pull/61)
New adversarial test scenarios simulate a tool whose description is swapped from benign to malicious mid-session via MCP's `notifications/tools/list_changed`, probing whether agents re-validate tool definitions before acting. **Why it matters:** protocol-level attack surfaces (not just prompt injection) are becoming standardized test targets as MCP matures — a sign the ecosystem is catching up to real deployment risks.

**5. `trust_remote_code=false` previously couldn't override tasks that hardcode remote execution** — [EleutherAI/lm-evaluation-harness#4584](https://github.com/EleutherAI/lm-evaluation-harness/pull/4584)
The fix makes an explicit `false` setting an actual veto over task-level remote code execution, closing a supply-chain-style gap where a malicious or careless eval config could execute arbitrary code regardless of user intent. **Why it matters:** evaluation harnesses are now part of the trusted-code attack surface for anyone benchmarking untrusted model/task combinations.

## Notable GitHub Releases & Tools

- **[xMannixx/Agent-Security-Guard v0.5.0 / v0.5.1](https://github.com/xMannixx/Agent-Security-Guard/releases/tag/v0.5.0)** — Closes gaps identified by its own benchmark: attacks through web pages, search, X, browser and `curl` are now stopped pre-execution, pushing InjecAgent-via-web-page from 561/1,054 to 1,054/1,054 stopped while adding zero friction to normal tasks. **Why it matters:** a concrete, benchmark-driven iteration cycle for agent injection defenses, now listed in the [Hermes plugin catalog](https://github.com/xMannixx/Agent-Security-Guard/pull/47).

- **[NVIDIA-NeMo/Guardrails — HiddenLayer AI Runtime Security rail](https://github.com/NVIDIA-NeMo/Guardrails/pull/2575)** — Adds a dedicated rail integrating HiddenLayer's runtime security checks across all four guardrail surfaces, alongside doc fixes correcting examples that still treated rail outcomes as raw booleans/scores instead of the newer `RailOutcome` type ([PR #2585](https://github.com/NVIDIA-NeMo/Guardrails/pull/2585)). **Why it matters:** expands NeMo Guardrails' third-party detection ecosystem, a widely used open-source LLM safety layer.

- **[TransformerLensOrg/TransformerLens v4.4.0](https://github.com/TransformerLensOrg/TransformerLens/releases/tag/v4.4.0)** — Interpretability-focused fixes including MoE execution correctness on MPS and explicit CUDA RNG forking for reproducible mechanistic interpretability experiments; companion PRs add provenance tracking for pretrained Jacobian lenses ([#2010](https://github.com/TransformerLensOrg/TransformerLens/pull/2010), [#2014](https://github.com/TransformerLensOrg/TransformerLens/pull/2014)). **Why it matters:** TransformerLens underpins much of the open mech-interp research stack; reproducibility and metadata-integrity fixes directly affect the trustworthiness of published interpretability results.

- **[sattyamjjain/agent-airlock v0.10.34](https://github.com/sattyamjjain/agent-airlock/releases/tag/v0.10.34)** — Adds a `ReadOnlySQLGuard` that inspects SQL generated by LLMs in tool arguments before execution (closing two CVEs), refreshes a malware-advisory snapshot to catch newly disclosed npm supply-chain malware, and fixes a shell-policy false positive on quoted backticks. **Why it matters:** targeted, CVE-linked hardening for the increasingly common pattern of LLM-generated SQL/shell commands in agent tool calls.

- **[wardenbot-ai/pytest-wardenbot v0.7.0](https://github.com/wardenbot-ai/pytest-wardenbot/releases/tag/v0.7.0)** — Ships the MCP lifecycle attack scenarios plus a preregistered evaluation run against local models, following open-science norms (plan published before results). **Why it matters:** a pytest-native adversarial testing framework for agent/MCP pipelines, now with preregistered (non-cherry-picked) benchmark methodology.
